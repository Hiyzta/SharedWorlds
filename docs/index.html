One world.
Any friend can host.

Shared Worlds keeps the newest Terraria world file in friends-only Steam Workshop items — one per account — so the group can pass hosting around without a server, a VPS, a NAS, or the original creator being online.

How it works Install GitHub

Status: 0.1.1 · early development · single-account Workshop flow tested

The problem

Terraria cannot merge two diverged worlds. If Alice plays alone and quits, only Alice's machine has the newest .wld and .twld. Her friends cannot host it. Steam Cloud is per-account. Steam Remote Play needs a host online. Somebody has to own the latest file — and somebody has to be able to hand it to the next host.

Steam Workshop is the only always-on, Valve-hosted storage available here. But only the owner of a Workshop item can push updates. Contributors are credit only. Sharing a Steam login is not acceptable.

How it works

01

One item per account

Every participant gets their own friends-only Workshop item for the world. One writer per item. No contributor permissions needed.

02

Snapshot on exit

When the authoritative host saves and exits, the mod writes a compressed snapshot: world.wld, world.twld, and a manifest.json with version, hash, parent hash, mods, and participant item IDs.

03

Query, verify, host

Before hosting, the mod reads version metadata from every known item, downloads only the newest candidate, verifies SHA-256, and starts Host & Play.

04

Fast-forward, never merge

If the candidate descends from the local version, it is a fast-forward. If the two branches are unrelated, the mod refuses to overwrite and shows a fork choice.

Alice ── save & exit ──► snapshot vN ── upload ──► Alice's item (friends-only)
                                                              ▲
                                                              │ metadata query
Bob ── sync / download ───────────────────────────────────────┘
  │
  └── Host & Play ──► session ──► snapshot vN+1 ── upload ──► Bob's item
                            │
                            └── chunked ModPacket transfer to connected players

Version identity

SHA256(SHA256(world.wld) || SHA256(world.twld))

Version numbers order the history; the hash and parent chain decide what is actually safe to install.

Metadata without downloads

A 5000-byte Workshop metadata header carries the world ID, version, hash, parent, host, and participant items. The full manifest travels inside the snapshot.

What you get

  • Shared Worlds screen on the main menu: versions, last host, sync status, invites.
  • Host from any account. The original creator is not special.
  • Open to friends: in-game panel → save → title → Host & Play with friends-only lobby visibility.
  • Fork detection with an explicit remote/local choice; the losing branch stays backed up.
  • Peer transfer in 16 KB verified chunks during a session.
  • Backups and retries: never swap an unverified file; keep pending uploads for later.

Architecture notes

Storage

Steam Workshop items are opaque folders. tModLoader only treats folders containing .tmod as mods; our snapshots are ignored by its mod scanner.

Steam API reachability

Mods compile against tModLoader's bundled Steamworks.NET, and tModLoader explicitly redirects that assembly to its own copy. Steam UGC is callable directly from mod code.

Host & Play

Terraria 1.4.4 starts a separate server process and reconnects the host client. Shared Worlds uses the game's own launcher, with a fallback to the normal Host & Play screen.

One writer

No API grants update rights to a collaborator. Per-account items are the only safe way to let every participant publish.

Safety

Hash before swap; backup before install; temp file then atomic move; refuse downgrades unless the user explicitly resolves a fork.

No backend

The mod writes only inside the tModLoader save directory. No HTTP, no telemetry, no always-on service.

Limitations, honestly

  • A host must be online to host. The original creator does not, but some participant does.
  • Friendship is access. Friends-only items cannot be read by non-friends. Losing a friendship loses that account's latest snapshot.
  • Propagation delay. A fresh upload can take a short while to become visible to other accounts. The mod retries and never installs unverified content.
  • Private is owner-only. A private item cannot be the shared storage primitive; friends-only is the correct setting.
  • No live conversion. “Open to friends” saves, returns to the title screen, and relaunches Host & Play.
  • Peer transfer is best-effort. It does not trap the host until every client ACKs; the Workshop snapshot is the durability guarantee.
  • Policy risk. Non-mod items in the tModLoader Workshop are a grey area. They are clearly labelled, friends-only, and contain no executable content.

FAQ

Does the original creator have to be online?

No. Each participant writes to their own Workshop item. The newest version can come from any account that hosted and saved.

Can two people host at the same time?

They can, but they will create a fork. The mod detects it by hash/parent chain and refuses to silently overwrite either branch. The group chooses; the other branch stays in local backups.

Why not one Workshop item with contributors?

Steam has no API for contributor upload rights. Only the item owner can update it. Contributors on the web page are credit only.

Why not Steam Cloud?

Steam Cloud is per Steam account. There is no supported way to share a Cloud file with another account.

What happens if Steam is offline?

Workshop storage is unavailable. The mod keeps local snapshots, uses peer transfer while connected, and keeps a pending upload for later. It never deletes a local world because a remote item is missing.

Is a Workshop storage item a mod?

No. It is a folder containing the world and a manifest. It contains no .tmod and no executable code. Do not subscribe to it as a mod.

How big are the uploads?

Normal worlds are a few MB to roughly 15 MB. The mod caps snapshots at 64 MB uncompressed, compresses transfers, and uploads once per changed session.
